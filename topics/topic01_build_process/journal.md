# Цель темы

Разобраться, каким образом программа на языке C превращается в исполняемый файл.

Главная задача — понять обязанности каждого этапа сборки, а не просто научиться писать код.

---

# Ход изучения

## 21.07.2026

### Первый эксперимент — `hello_without_include.c`

Создана программа, использующая `printf()`, но без подключения заголовочного файла `stdio.h`.

#### Цель

Проверить, как компилятор реагирует на использование функции без её предварительного объявления.

#### Результат

Во время компиляции GCC сообщил, что функция `printf()` неизвестна.

#### Вывод

Директива `#include` не является частью выполняемой программы.

Она обрабатывается препроцессором ещё до начала компиляции и подставляет необходимые объявления в исходный код.

---

### Второй эксперимент — препроцессор

Использована команда:

```bash
gcc -E hello.c -o hello.i
```

#### Результат

- программа увеличилась примерно с 5 до 1500 строк;
- директива `#include` исчезла;
- вместо неё было подставлено содержимое заголовочных файлов;
- результат работы препроцессора всё ещё представляет собой обычный текст на языке C.

#### Вывод

Компилятор работает не с исходным файлом, а с текстом, который предварительно подготовил препроцессор.

---

## 22.07.2026

### Эксперимент с объявлением функции

Создан прототип функции `sum()`, однако её реализация отсутствовала.

#### Результат

Компиляция завершилась успешно.

На этапе линковки появилась ошибка:

```
undefined reference to 'sum'
```

#### Вывод

Компилятору достаточно объявления функции для проверки корректности её использования.

Однако линковщик обязан найти её реализацию. Если реализация отсутствует, создание исполняемого файла невозможно.

---

## 23.07.2026

### Эксперимент без прототипа

Прототип функции был удалён, а сама функция оставлена после `main()`.

#### Результат

Компилятор сообщил:

```
implicit declaration of function 'sum'
```

#### Вывод

Компилятор анализирует программу последовательно сверху вниз.

Чтобы использовать функцию до её определения, необходимо заранее сообщить компилятору о её существовании при помощи прототипа.

# Итоги темы

За время изучения удалось сформировать общее представление о процессе сборки программы.

```
Исходный код
        │
        ▼
Препроцессор
        │
        ▼
Компилятор
        │
        ▼
Линковщик
        │
        ▼
Исполняемый файл
        │
        ▼
Процессор
```

Стало понятно, какую роль выполняет каждый этап и почему ошибки могут возникать на разных стадиях сборки.
