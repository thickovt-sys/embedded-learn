## Эксперимент №3 — Адреса глобальной и локальной переменной

### Код

Вывод адресов:

- глобальной переменной;
- локальной переменной.

### Гипотеза

Предполагал, что при каждом запуске программы адреса обеих переменных будут изменяться.

### Эксперимент

Программа была запущена пять раз.

Полученные результаты показали:

- адрес глобальной переменной оставался одинаковым;
- адрес локальной переменной менялся между запусками.

### Вывод

Глобальные и локальные переменные размещаются по разным правилам.

Также стало очевидно, что память программы разделена на области с разным назначением.

---

## Основные выводы

- Имя переменной необходимо только во время разработки и компиляции.
- Во время выполнения программы процессор работает исключительно с адресами.
- Локальные переменные располагаются в одной области памяти.
- Глобальные и локальные переменные живут по разным правилам.
- Следует различать гарантии языка C и особенности конкретной реализации.
- Для встроенных систем и программ под управлением операционной системы механизм назначения адресов переменным отличается.

# Эксперимент 3

Исследование расположения глобальной и локальной переменных в памяти.

### Код

Использовалась программа, выводящая адреса глобальной и локальной переменных.

### Наблюдение

После нескольких запусков программы:

- адрес глобальной переменной оставался неизменным;
- адрес локальной переменной изменялся между запусками.

### Вывод

Глобальные и локальные переменные располагаются в разных областях памяти.

Локальные переменные создаются во время выполнения функции и размещаются в стеке.

# Эксперимент 4

Получение ассемблерного кода.

Команда:

```bash
gcc -S experiment4.c -o experiment4.s
```

### Наблюдение

В полученном файле:

- полностью исчез язык C;
- появилась директива

```asm
.globl global
```

- переменная описывалась как

```asm
global:
.long 42
```

- доступ к переменной выполнялся инструкцией

```asm
movl global(%rip), %eax
```

### Вывод

Компилятор не создаёт машинный код напрямую.

Он сначала переводит программу на язык ассемблера.

Имена переменных больше не используются процессором как элементы языка C.

Компилятор оставляет информацию, необходимую последующим этапам сборки программы.

---

# Основные выводы темы на данный момент

- процессор не знает язык C;
- процессор работает только с инструкциями;
- имена переменных существуют только на ранних этапах сборки;
- между компилятором и линковщиком существует этап генерации ассемблерного кода;
- линковщик связывает объектные файлы и разрешает ссылки между функциями и переменными.

# Topic 02 — Personal Learning Log

## День 2 обучения темы (28.07.2026)

Сегодня тема памяти начала складываться в единую картину.

Главное открытие дня — стековый кадр.

До этого я представлял стек просто как область памяти для локальных переменных. Теперь понимаю, что при каждом вызове функции поверх существующего стека создаётся новый стековый кадр, который уничтожается после завершения функции.

Самым неожиданным выводом стало различие между адресом памяти и временем жизни объекта.

Раньше мне казалось, что после уничтожения локальной переменной исчезает и сам адрес.

Теперь понимаю:

- адрес остаётся обычным числом;
- исчезает только право объекта пользоваться этой областью памяти.

Именно поэтому возвращение адреса локальной переменной считается ошибкой.

Также окончательно замкнулась цепочка выполнения программы.

Теперь представляю путь программы следующим образом:

Исходный код
→ препроцессор
→ компилятор
→ ассемблер
→ объектный файл
→ линковщик
→ исполняемый файл
→ загрузчик операционной системы
→ процессор.

После этого становится значительно легче понимать происходящее "под капотом", а не воспринимать язык C как набор синтаксических правил.
