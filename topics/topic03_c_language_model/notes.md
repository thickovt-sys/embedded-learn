## Основная идея темы

Язык C является договором между программистом и компилятором.

Процессор не знает:

- что такое int;
- что такое char;
- что такое float;
- что такое переменная.

Он выполняет только машинные инструкции.

---

## Для чего существуют типы

Тип нужен компилятору.

Он сообщает:

- размер объекта;
- допустимые операции;
- способ интерпретации данных;
- правила генерации машинного кода.

---

## Почему нельзя отказаться от типов

Без системы типов компилятор не сможет:

- автоматически определять размер объектов;
- понимать смысл операций;
- находить множество ошибок ещё до запуска программы.

---

## Первое правило Topic 03

Тип — это описание смысла объекта для компилятора.

Не для процессора.

Не для памяти.

Именно для компилятора.
## Тип, смысл данных и представление

Тип является частью модели языка C и используется компилятором при анализе программы.

Основной вывод:

> **Тип нужен компилятору для определения смысла объекта и допустимых операций над ним.**

Тип нельзя сводить только к размеру объекта в памяти.

Одни и те же байты потенциально могут использоваться как представление объектов разных типов. При этом сами байты не обязаны содержать отдельную информацию, сообщающую процессору название типа C.

Важно различать уровни:

```text
исходный код C
      ↓
компилятор знает типы
      ↓
определяет смысл операций
      ↓
формирует машинный код
      ↓
процессор выполняет инструкции
```

Процессор не получает исходный C-код и не обязан знать, что конкретные данные были описаны в C как `int`, `unsigned int` или другой тип.

Таким образом, информация о типе прежде всего используется на уровне языка и компилятора. После компиляции последствия этой информации выражаются уже в машинном коде и способе выполнения операций.

### Модель, сформированная на данном этапе

```text
тип
 ↓
смысл объекта
 ↓
допустимые операции
 ↓
решения компилятора
 ↓
машинный код
```

Пока не следует делать более сильные выводы о конкретном представлении объектов, aliasing, effective type, ABI и других механизмах. Эти темы будут введены позже после формирования базовой модели.

### Ключевая идея

> **Биты сами по себе являются представлением данных. Их смысл определяется контекстом программы и моделью типа.**
## Представление данных и порядок байтов

Физическое содержимое памяти и смысл данных — не одно и то же.

Для исследования использовался объект:

```c
int a = 1;
```

и указатель:

```c
unsigned char *p = (unsigned char *)&a;
```

Это позволило обратиться к той же области памяти как к отдельным байтам.

На используемой системе:

```text
int a = 1;

01 00 00 00
```

Для:

```text
int a = 257;
```

получили:

```text
01 01 00 00
```

На основании экспериментов установлено:

> **На исследованной системе младший байт многобайтного значения располагается по меньшему адресу.**

Такой порядок байтов называется **little-endian**.

### Важное различие

Преобразование:

```c
unsigned char *p = (unsigned char *)&a;
```

не изменяет содержимое объекта `a`.

Мы не создаём новую копию байтов и не меняем их расположение. Мы получаем другой способ обратиться к той же области памяти.

Таким образом:

```text
объект int
    ↓
те же байты в памяти
    ↓
обращение через unsigned char *
    ↓
отдельные байты
```

### Представление и интерпретация

Одна последовательность байтов сама по себе не обязана однозначно сообщать, какое значение или смысл ей приписывает программа.

Для интерпретации важен контекст:

```text
байты
 ↓
тип / контекст программы
 ↓
интерпретация
 ↓
значение
```

При работе с многобайтным объектом также необходимо учитывать порядок расположения байтов.

### Граница текущего знания

Эксперименты показали поведение конкретной используемой системы. Пока не следует распространять его на все архитектуры и платформы.

Также пока не рассматриваются более сложные правила C, связанные с aliasing, effective type и допустимостью различных способов доступа к объектам. Эти вопросы будут изучены позже.

### Ключевой вывод

> **Байты — это физическое представление данных в памяти. Их смысл определяется тем, как программа и компилятор интерпретируют эту область памяти.**

## Signed и unsigned

Для 8 бит существует:

```text
2⁸ = 256
возможных комбинаций.

Unsigned

Все комбинации используются для неотрицательных значений:

0 ... 255
Signed

В two's complement диапазон:

-128 ... 127

Один и тот же набор битов может иметь разное значение в зависимости от типа и способа интерпретации.

Например:

11111110

unsigned → 254
signed   → -2
Указатели

У каждого объекта существует адрес, по которому он расположен в памяти.

int a = 42;

Получение адреса:

&a

Указатель позволяет сохранить этот адрес:

int *p = &a;

Здесь:

a — объект типа int;
&a — адрес объекта a;
p — объект-указатель;
int * — тип указателя на int.

Разыменование:

*p

означает обращение к объекту, адрес которого хранится в p.

Например:

int a = 42;
int *p = &a;

*p = 100;

После записи объект a содержит 100.

Модель:

объект a
   ↓
адрес
   ↓
указатель p
   ↓
разыменование *p
   ↓
объект a
Важное различие

Указатель хранит адрес, а не само значение объекта.

a  → значение
p  → адрес a
*p → объект по этому адресу
Связь с предыдущими экспериментами

Ранее использовалось:

unsigned char *p = (unsigned char *)&a;

Это уже было практическим использованием указателя для доступа к области памяти объекта a через unsigned char.
